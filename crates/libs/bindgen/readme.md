# windows-bindgen

Generate a focused set of Rust bindings from Windows metadata (`.winmd`). Bundled metadata covers
Win32 and WinRT; custom metadata can describe additional APIs. Applications and libraries can use
these bindings instead of depending on the umbrella `windows` or `windows-sys` crates.

- 📦 [crates.io](https://crates.io/crates/windows-bindgen)
- 📖 [docs.rs](https://docs.rs/windows-bindgen)
- 🧩 [Samples](https://github.com/microsoft/windows-rs/tree/master/crates/samples/bindgen)
- 📁 [Source](https://github.com/microsoft/windows-rs/tree/master/crates/libs/bindgen)

## Generate bindings

Install `rustfmt` with `rustup component add rustfmt`. For build-time generation, add the generator
as a build dependency and `windows-core` for the default typed bindings:

```toml
[dependencies]
windows-core = "0.101"

[build-dependencies]
windows-bindgen = "0.101"
```

In `build.rs`:

```rust,no_run
use windows_bindgen::*;

fn main() {
    println!("cargo:rerun-if-changed=build.rs");
    builder().filter("GetTickCount64").write();
}
```

In `src/main.rs`:

```rust,ignore
mod bindings {
    include!(concat!(env!("OUT_DIR"), "/bindings.rs"));
}

fn main() {
    println!("{}", unsafe { bindings::GetTickCount64() });
}
```

Run `cargo run` on Windows. Without `.output(...)`, bindgen writes `bindings.rs` in Cargo's
`OUT_DIR`. Use explicit output paths outside build scripts and when generating multiple files.

Bindgen does not emit Cargo dependency-tracking directives. The example watches only `build.rs`;
declare any other inputs your script reads, including metadata and filter files, with
`cargo:rerun-if-changed`.

## Commit bindings

For a published library, consider committing generated bindings so consumers do not build the
generator. This also works for applications that prefer to regenerate only when their API
selections change.

To switch the example above, add `.output(concat!(env!("CARGO_MANIFEST_DIR"), "/src/bindings.rs"))`
to the builder in `build.rs`, replace the `include!` module with `mod bindings;`, and build once.
Then remove `build.rs`, move `windows-bindgen` to dev-dependencies, and add a regeneration test:

```toml
[dev-dependencies]
windows-bindgen = "0.101"
```

```rust,no_run
#[test]
fn generate_bindings() {
    windows_bindgen::builder()
        .filter("GetTickCount64")
        .output(concat!(env!("CARGO_MANIFEST_DIR"), "/src/bindings.rs"))
        .write();
}
```

Keep the runtime dependencies and commit `src/bindings.rs`. Do not mix handwritten and generated code.
Run `cargo test generate_bindings`, then run Cargo again to compile any changed bindings. CI should
reject changes to committed generated files. Regenerate after changing filters, before adding code
that uses newly selected APIs. A separate generator tool is another option.

The [thread-pool sample](https://github.com/microsoft/windows-rs/tree/master/crates/samples/bindgen/thread-pool-work)
demonstrates committed raw bindings regenerated by a test.

## Select APIs

Filters select native names, including any `A` or `W` suffix. Signature dependencies are included
automatically. Qualify names when more than one namespace defines them. Output is a flat list of
items; selecting the same name from two namespaces fails to compile unless you exclude one or use
`.modules()`.

| Filter | Selects |
| --- | --- |
| `GetTickCount64`, `S_OK`, `HWND` | A function, constant, or type |
| `Windows.Win32.GetTickCount64` | A qualified Win32 function |
| `Windows.Foundation` | A namespace and its descendants |
| `ISequentialStream` | An interface and its methods |
| `ISequentialStream::{}` | The interface without its callable methods |
| `Uri` | A runtime class, its methods, and its factories |
| `IDataReader::ReadByte` | One interface method |
| `IDataReader::{ReadByte, ReadUInt32}` | Several methods |
| `IDataReader::ByteOrder` | A property's getter and setter |
| `AsyncStatus::{Completed, Error}` | Selected enum variants |
| `!Windows.Foundation.Collections` | Exclude a namespace and its descendants |
| `!ISequentialStream::Write` | Exclude a member |

Dots and `::` both separate path segments. Groups abbreviate separate filters; `*` wildcards are
not supported. Use native member or overload names, not renamed Rust methods.

An interface reached only through a signature can be a name-only declaration. Select its name
to include its methods, or select individual methods. An explicit `Interface::{}` is useful when
you only pass, store, or cast the interface; it does not remove methods requested by other filters.

Exclusions do not repair dependent selections; excluding a required type can produce bindings that
fail to compile. See
[`Bindgen::filter`](https://docs.rs/windows-bindgen/latest/windows_bindgen/struct.Bindgen.html#method.filter)
for rule precedence, constructors, accessors, events, and nested groups.

Use `.filters([...])` for several selections or `.filter_file("apis.txt")` for a text file.
Files separate filters with whitespace and support multiline groups, trailing commas, and `//`
comments:

```text
ISequentialStream::{
    Read,
    Write, // Include both methods
}
```

The bundled Win32 metadata uses `Windows.Win32`, not the umbrella crates' Cargo feature names.

## Choose an output style

| Option | Result |
| --- | --- |
| Default | Minimal typed bindings using `windows-core` |
| `.full()` | Adds class wrappers, inherited forwarders, handle and function wrappers |
| `.sys()` | Raw bindings using `windows-link` |
| `.modules()` | One module per namespace instead of a single flat list |
| `.implement("Windows.Win32.ISequentialStream")` | Implementation traits for a selected interface |

For raw bindings, add `.sys()` and use `windows-link = "0.100.1"` instead of `windows-core`.
`sys` and `full` are mutually exclusive. Add any focused support crates referenced by typed output.
For example, generated async signatures use `windows-future`; add it as a runtime dependency
(`windows-future = "0.101"`).

Minimal bindings expose raw Win32 function signatures, so callers handle output parameters and
convert HRESULTs with `.ok()` where appropriate. Their WinRT methods use `&str` inputs and `String`
outputs instead of `HSTRING`. To call methods on another COM or WinRT interface, select that
interface and cast to it with `windows_core::Interface::cast`.

When migrating from `windows`, `.full()` can reduce changes by adding function wrappers that turn
HRESULTs and output parameters into `Result` values. Neither style initializes COM or changes the
native APIs' threading and ownership requirements.
The [COM URI sample](https://github.com/microsoft/windows-rs/tree/master/crates/samples/bindgen/com-uri)
uses full bindings, while the
[data-protection sample](https://github.com/microsoft/windows-rs/tree/master/crates/samples/bindgen/data-protection)
uses minimal WinRT bindings and `windows-future`. Both scope native-name lint expectations to the
generated bindings module.

With flat bindings, a renamed `windows-core` dependency can be imported as `windows_core` inside
the generated bindings module, for example `use runtime as windows_core;`.

To implement interfaces in Rust, use
[`Bindgen::implement`](https://docs.rs/windows-bindgen/latest/windows_bindgen/struct.Bindgen.html#method.implement)
with a qualified name or namespace prefix. Required base interface implementations are included
automatically unless excluded or supplied by a referenced crate. Full mode includes implementation
traits for interfaces not marked `ExclusiveTo`; an explicit implementation selection replaces that
default.

## Use custom metadata

With no input, bindgen uses bundled Windows metadata. `.input("component.winmd")` replaces that
default; add `.input_default()` when the component also references Windows definitions.
Use [windows-rdl](https://docs.rs/windows-rdl) to compile RDL or
[windows-clang](https://docs.rs/windows-clang) to start from headers. Upgrade metadata producers
and binding generators together.
